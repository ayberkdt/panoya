# 11 — Typed reactive calculation engine

## Design
Notebooks are reactive documents. A formula can use named bindings to stable block outputs, e.g. `cash + bank`, bindings `{cash:{blockId:A,outputKey:'value'},bank:{blockId:B,outputKey:'value'}}`. UI binding picker searches pages/blocks and shows types/units. Persist expression + bindings; graph derived. No title lookup at execution. Outputs tagged: number, decimal, money, quantity(unit), string, boolean, datasetRef, vector, missing, error. Never coerce mixed types without explicit conversion. Missing propagates as explicit status; division by zero, overflow, invalid dimensions, nonfinite results typed errors. Money uses decimal strings; rounding policy per 14. MVP no arbitrary JavaScript, Python, assignment, object indexing, import, property traversal, file/network access, randomness/time without explicit input snapshot.

## Grammar and evaluator
Implement small tokenizer + Pratt or recursive descent parser, AST with source spans. Tokens: decimal/exponent literal, identifier, parentheses, comma, + - * / ^, comparisons, allowlisted function calls. Initial functions abs,min,max,sum,mean,sqrt,log,exp,sin,cos,round; specify radian convention, domains and numeric types. Document precedence: power right associative, unary minus lower than power (`-2^2=-4`), multiplication before addition. No implicit multiplication initially. Decimal and float arithmetic explicit; forbid silently converting money into dimensionless float. If using math.js for pure functions, do not expose generic evaluate; validate AST and only dispatch allowed functions. Limits initial: 4096 chars, 512 AST nodes, nesting 32, vector 10k, worker deadline 500 ms with cancellation; tune measured. No recursion, unbounded loops or user functions. Formula output version depends on expression, input revisions, evaluator version.

## Graph algorithm
Edges source→consumer from validated bindings, dataset/FX dependencies as synthetic source IDs. Build adjacency and reverse map; when adding edge detect cycles with DFS or topological ordering. On cycle report path, invalidate cycle and downstream; keep editable definition, do not compute stale result as current. On source commit: collect reachable consumers, topological sort subgraph (Kahn), evaluate once each, publish versioned result only if snapshot generation still current. Complexity O(V+E) over affected graph excluding actual evaluation. Missing/deleted source yields REF_ERROR; invalid dependency yields UPSTREAM_ERROR with source link. Rebuild graph on load/migration, no persisted graph authority. Evaluate cross-page same workspace even if page closed. Worker receives serializable snapshots; ignore stale job result after new commit. Detect and cancel overbudget jobs; UI stays responsive.

## Example
A cash=300 EUR, B bank=200 EUR, C=A+B=500 EUR, D=FX(C, TRY) with explicit snapshot rate 50 TRY/EUR=25000 TRY. E=travelBudget 320 EUR, F=C-E=180 EUR. Change A to 400: C=600, D=30000, F=280. Adding C as input to A formula creates cycle. Deleting B yields missing reference, not 300 total. FX function can be separate currency block; do not silently fetch rates during pure evaluation.

## Tests
Parser precedence and malformed expressions; unknown/forbidden identifier/prototype keys; adversarial nested AST and huge exponent; NaN/Infinity; cross-currency arithmetic rejected; graph diamond evaluates once, cross-page invalidation, cycles, missing refs, stale worker response, duplicate remapping; compare against independent analytic fixtures. Document numeric tolerances (e.g. float abs 1e-12 + rel 1e-10 for small fixtures); decimal money exact after specified rounding. Add property tests for DAG topological order and commutative operations where valid.
