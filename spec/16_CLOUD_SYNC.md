# 16 — Optional cloud synchronization and conflict resolution

## Principles
Single user across devices; no live multi-user editing. Supabase optional; local mode never requires network. Sign-in (email OTP/magic link or supported alternative), explicit attach local workspace to account; avoid merging different users. Account-scoped local DB namespace, logout locks user namespace; offer export/clear with confirmation, do not expose former user's cached notes to next account. Supabase Auth session handling; access token refresh via SDK; no service-role key in frontend. Cloud data is not end-to-end encrypted by this design; disclose. RLS on all user tables and private storage. Auth failure keeps local changes recoverable.

## Server model and API
Postgres entities mirroring canonical schema, workspace owner FK and composite FKs; remoteVersion assigned server on each mutation, workspace-scoped monotonically increasing change sequence. `sync_changes(workspace_id, seq, entity_id, entity_type, version, tombstone, payload)`; `sync_ops(workspace_id, device_id, op_id, request_hash, result)` idempotency ledger. Server transactional RPC validates auth/ownership, schema, allowed fields, expected remote versions, subtree invariants and quotas. Lock workspace row for sequence allocation and topology-changing batches; never rely on wall-clock last-write-wins. RLS policies USING + WITH CHECK, least privilege; RPC security invoker preferred, if definer required fixed search_path, explicit owner checks and revoke public execute. No direct client mutation paths bypassing sync constraints. All change log/ops access owner-scoped. Attachments private bucket with owner path, signed access short-lived and checked; server validates entity association.

## Protocol
1. Local command transaction writes entity changes + durable outbox operation with UUID, expected versions and base snapshot. Local-only workspace retains canonical state for initial attach; bootstrap sends complete consistent snapshot in bounded batches or atomic staged import.
2. One sync leader per workspace on device where supported (Web Locks + fallback lease); transport idempotency handles duplicate requests. Push FIFO per workspace, dependent operations wait until prior server versions known. Unsent updates may compact only if no references/history semantics lost; immutable in-flight op.
3. Server validates entire command batch atomically, returns accepted versions/sequence or conflict details. Same op ID+hash returns previous result, same ID different hash rejected. Crash after server commit before ack safe via retry.
4. Client transaction applies ack + remote versions, rebases pending local operations only when known safe, never overwrites newer local content. Pull changes ordered by sequence cursor, paginated; apply all received batch atomically and advance cursor only after commit. Server emits command boundaries so multi-entity changes not partially visible. Invalid payload quarantine + stop cursor advancement with recovery, not silent skip.
5. Remote change with pending local edit: if different independent entities merge normally; same entity and overlapping changes create explicit conflict. Nonoverlap field auto-merge only after three-way compare and invariants validation (P1); rich-text same block conflict preserve both copies, user chooses keep local/remote/duplicate or manual merge. Deletion vs edit conflict retains edit recovery. Never last-writer silently wins. Resolution creates new op against latest version.
6. Tombstones retained; MVP no automatic server tombstone pruning. Future log compaction requires snapshot epoch + cursor expiry + full resync that preserves pending local changes. Keep trash and tombstones distinct. Realtime notification optional hint; pull authoritative. Network reconnect jitter/exponential backoff, abort and retry; display local saved/pending/syncing/synced/conflict/auth error independently.

## Conflict and failure tests
Two users A/B: neither select/insert/update/delete other's data or blobs via API/RPC, anonymous denied. Two devices same user create simultaneously, edit different blocks, edit same block, move same folder and concurrent cycle attempt, offline edit vs remote delete, repeated op, lost ACK, stale cursor, pull pagination with command boundaries, interrupted apply, auth expiry and re-login, initial attach with nonempty cloud, quota rejection. Server integration tests against local Supabase; hosted verification separate and requires credentials. No auto production deploy or migration; document exact setup and pending steps. Sync is not backup: remote deletion can propagate, separate export/restore mandatory.
